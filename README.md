# Plan a dependency review from public release cadence

A long interval between releases can affect upgrade planning. It does not establish that maintainers have stopped working. This study will test a small retrospective release-gap benchmark and a local review exercise, using a fixed cohort of eight public repositories.

**State: bounded source metadata checked; analysis pending.** The current snapshot contains 484 minimal release records from eight repositories, independently reconstructed from 18 private originals in 6,024 source conditions. No predictive result, deployment or actual maintenance interruption is established. The [protocol](PROTOCOL.md) fixes source bounds, time and repository separation, candidate settings and publication checks. A current API snapshot cannot recreate the original historical availability of edited or deleted release records.

Development uses 168 training origins and 30 validation origins from four projects. All nine authored settings are retained; the 60-day cadence split with prior strength 1 has validation macro Brier 0.233250 versus 0.323495 for the simple pooled baseline. These are preliminary retrospective scores; the four other projects and later dates are still protected. The selected cutpoint and prior are grid-boundary choices, not a global optimum.
